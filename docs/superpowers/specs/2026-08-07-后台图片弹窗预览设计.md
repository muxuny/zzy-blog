# 后台图片弹窗预览设计

## 背景

后台“资源管理”已合并标签和图片素材管理。图片素材当前以 64x48 缩略图卡片展示，适合快速浏览数量和删除，但无法看清图片细节。图片列表接口已经返回 `url`、文件名、大小、上传人和创建时间，前端具备直接加载原图的条件。

## 目标

- 在资源管理图片素材列表中增加大图预览能力。
- 保持当前后台管理视觉风格，不重排资源管理页主体结构。
- 复用现有图片分页接口和图片 `url`，不新增后端接口、数据库表或字段。
- 让管理员能在预览中看清图片，并快速复制图片地址或删除当前图片。

## 非目标

- 不实现图片编辑、裁剪、替换、重命名或批量操作。
- 不新增图片详情接口，不改变上传、删除和分页接口。
- 不调整图片存储方式和访问权限。
- 不把图片列表改为全屏图库或右侧详情栏。

## 现状

- 前端页面：`blog-frontend/src/views/admin/Resources.vue`
- 图片接口：`GET /api/admin/upload/images?page&size`
- 删除接口：`DELETE /api/admin/upload/image/{id}`
- 图片实体：`Image` 包含 `originalName`、`filename`、`size`、`mimeType`、`url` 等字段
- 当前图片卡片只展示小图、名称、大小、上传人和删除按钮

## 交互设计

图片卡片保留当前两列网格和小缩略图。缩略图改为可点击按钮，并在卡片操作区增加“预览”按钮，二者都打开同一个预览弹窗。

预览弹窗内容：

- 大图展示区：使用图片 `url` 加载原图，按容器等比缩放，最大高度限制在视口内，避免撑出屏幕。
- 图片信息：展示原始文件名、文件大小、上传人、上传时间和图片地址。
- 操作按钮：复制图片地址、删除图片、关闭弹窗。

删除行为沿用现有删除接口。若从弹窗删除当前图片，删除成功后关闭弹窗，并按现有分页删除逻辑刷新当前页或回退到上一页。

## 响应式与可访问性

- 桌面端弹窗宽度控制在页面可读范围内，大图居中显示。
- 移动端弹窗宽度接近屏幕宽度，图片高度随视口收敛。
- 缩略图按钮和预览按钮提供明确的 `aria-label`。
- 无图片 URL 时不打开弹窗，并提示图片地址不可用。

## 异常处理

- 图片加载失败时，弹窗保留图片信息并显示无法预览的提示。
- 复制图片地址失败时显示错误提示，不影响弹窗状态。
- 删除失败沿用全局请求错误处理，弹窗不主动关闭。

## 测试与验证

前端建议覆盖：

- 资源管理页存在图片预览弹窗结构。
- 图片缩略图和“预览”按钮都会触发预览。
- 弹窗内展示大图、元信息、复制地址和删除入口。
- 从弹窗删除图片后关闭弹窗并刷新图片列表。

最终验证命令：

```powershell
cd D:\03PerProject\blog-frontend

npm.cmd run build
```

## 验收标准

- 管理员在资源管理图片素材中可以打开大图预览。
- 大图预览不破坏当前资源管理页布局和视觉风格。
- 管理员可以从预览弹窗复制图片地址。
- 管理员可以从预览弹窗删除当前图片，列表刷新逻辑正确。
- 本功能不产生数据库增量脚本。
