# 页面文案配置设计

## 背景

当前多个功能页在页面头部写死了 `eyebrow`、主标题和描述。随着页面数量增加，后续每次调整口径都需要改前端代码。用户已确认将这些页面级导语改为后台可维护配置，并已验收后台配置页 HTML 原型：`docs/prototypes/页面文案配置原型.html`。

## 目标

- 管理员可在后台维护功能页页面级 `eyebrow`、`title`、`description`。
- 公开页、登录页、用户页、创作中心和后台页读取同一套页面文案配置。
- 前端保留本地默认文案，接口失败或配置缺失时自动回退，避免页面空白。
- 数据库只提交增量脚本，不代用户执行。

## 后端设计

新增 `page_copy` 表保存页面文案配置，包含公共字段：`id`、`created_by`、`created_at`、`updated_by`、`updated_at`、`deleted`、`version`。

核心字段：

- `copy_key`：页面标识，唯一，例如 `home.hero`。
- `page_name`：后台列表展示名称，例如 `首页`。
- `page_group`：分区，例如 `公开与用户页`。
- `eyebrow`：眉标，可为空字符串。
- `title`：主标题，必填。
- `description`：描述，可为空字符串。
- `sort_order`：后台列表排序。

接口：

- `GET /api/page-copies`：公开读取全部可用配置，用于前端覆盖本地默认文案。
- `GET /api/admin/page-copies`：管理员读取配置列表。
- `PUT /api/admin/page-copies/{copyKey}`：管理员更新单页 `eyebrow`、`title`、`description`。
- `POST /api/admin/page-copies/reset`：管理员恢复全部默认配置。

服务层维护一个固定默认清单。读取时会先保证默认配置存在，再返回按 `sort_order` 排序的记录。更新时只允许更新默认清单内的 `copyKey`，避免后台写入游离配置。

## 前端设计

新增页面文案模块：

- `src/utils/pageCopy.js`：定义 16 个默认文案、分组顺序、占位符替换和默认合并逻辑。
- `src/api/pageCopy.js`：封装公开读取、后台读取、保存和恢复默认接口。
- `src/stores/pageCopy.js`：Pinia store，缓存文案配置，页面加载时按需拉取；接口失败时保留默认文案。
- `src/views/admin/PageCopies.vue`：后台配置页，按原型实现页面列表、编辑表单、预览和保存/恢复默认。

现有功能页把硬编码头部改为读取 `usePageCopyStore().resolveCopy(copyKey, params)`。动态页面按状态选择 key：

- 创作写作页：创建态用 `creator.article.create`，编辑态用 `creator.article.edit`。
- 后台文章编辑页：创建态用 `admin.article.create`，编辑态用 `admin.article.edit`。
- 标签页：用 `tag.index`，标题默认 `{tagName}`，渲染时替换为路由标签名。

## 错误处理

- 公开读取失败：前端静默保留默认文案，不弹出错误提示。
- 后台列表读取失败：显示警告提示，保留默认文案列表供页面可读。
- 保存失败：沿用请求拦截器错误提示；表单保持当前输入。
- 恢复默认失败：沿用请求拦截器错误提示；不改本地列表。
- 描述为空：页面不渲染描述行，避免空白占位。

## 测试策略

- 后端服务测试覆盖默认配置补齐、只允许更新已知 key、保存 trim 后字段、恢复默认。
- 后端控制器测试覆盖公开读取、管理员读取、管理员更新和恢复默认的路由委托与权限注解。
- 数据库配置测试覆盖 `page_copy` 增量脚本和 `init.sql` 表结构包含公共字段且无破坏性语句。
- 前端工具测试覆盖默认清单数量、占位符替换、远端配置合并、未知 key 回退。
- 前端源码测试覆盖后台路由、导航入口、配置页和关键页面使用 `resolveCopy`。

## 验收口径

- 未执行增量 SQL 时，前端页面仍显示本地默认文案。
- 执行增量 SQL 并启动后端后，管理员可进入后台“页面文案”维护 16 个页面导语。
- 修改保存后，刷新对应功能页能看到自定义文案。
- 点击“恢复默认”后，配置回到当前代码默认清单。
