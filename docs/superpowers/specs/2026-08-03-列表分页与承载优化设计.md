# 列表分页与承载优化设计

## 背景

当前博客的主要业务列表已经具备分页能力：公开首页文章列表、我的文章、后台文章管理、我的收藏和阅读历史都通过分页接口获取数据，并在 `total > size` 时显示分页控件。

但仍有一些页面为了简化实现使用固定大 `size` 或全量拉取：标签文章页固定拉取 100 篇文章，后台用户管理固定拉取 100 个用户，资源管理图片固定拉取 100 张，资源管理标签全量拉取，后台仪表盘通过大列表在前端计算统计。随着数据增长，这些页面会出现列表过长、页面承载变重、统计口径不稳定的问题。

## 目标

- 补齐固定大 `size` 或全量拉取页面的分页体验。
- 保持仪表盘统计为全站口径，由后端聚合查询提供，不用分页结果冒充全量统计。
- 保留公开首页、我的文章、后台文章管理、我的收藏和阅读历史现有分页能力，仅做回归保护。
- 不新增数据库表或字段，不执行数据库脚本。
- 继续沿用 Vue 3、Element Plus、Spring Boot、MyBatis-Plus 和现有 `PageResult` 响应结构。

## 非目标

- 不实现评论、点赞、热门排行、阅读趋势或游客本地阅读历史。
- 不重做页面视觉风格，只在现有视觉系统内补分页控件和状态文案。
- 不把文章编辑页的标签选择、公开首页标签导航、创作分组列表改为分页；这些属于小集合选择器或导航入口，后续如数据量明显增长再做搜索式选择。
- 不让仪表盘统计按分页结果计算。

## 当前分页现状

已分页：

- 公开首页文章列表：`GET /api/articles?page&size`
- 我的文章：`GET /api/my/articles?page&size`
- 后台文章管理：`GET /api/admin/articles?page&size`
- 我的收藏：`GET /api/my/favorites?page&size`
- 阅读历史：`GET /api/my/reading/history?page&size`

需补齐：

- 标签文章页：当前 `GET /api/articles?tagId&size=100`
- 后台用户管理：后端支持分页，前端当前 `GET /api/admin/users?size=100`
- 资源管理图片：后端支持分页，前端当前 `GET /api/admin/upload/images?page=1&size=100`
- 资源管理标签：当前公开标签接口全量返回，后台资源管理复用该接口
- 仪表盘统计：当前通过 `size=200` 文章列表和 `size=100` 用户列表在前端聚合

## 设计方案

### 标签文章页

标签文章页保留通过标签名进入的路由 `/tag/:name`。页面加载时仍先用公开标签列表解析标签名到标签 ID，然后按 `page=1,size=10,tagId=...` 获取文章分页。

页面增加 `page`、`size`、`total` 状态。文章数量展示使用接口返回的 `total`，不是当前页数量。分页切换时只刷新当前标签下文章流，不重新解析标签名。若标签不存在，展示空状态。

### 后台用户管理

后台用户管理接入已有 `GET /api/admin/users?page&size`。页面增加分页控件、总数展示和当前页状态。

顶部“待审核”提示只表示当前页待审核数量，文案写为“本页 X 个待审核”，避免被理解为全站统计。全站待审核用户数量交给仪表盘聚合接口展示。

审核通过或禁用后刷新当前页。如果当前页因操作后为空且不是第一页，回退到上一页。

### 资源管理图片

资源管理图片使用已有 `GET /api/admin/upload/images?page&size`。图片素材数量展示使用分页响应 `total`，缩略图区域只展示当前页。

上传成功后回到第一页刷新，方便看到最新上传图片。删除后刷新当前页；如果当前页为空且不是第一页，回退到上一页。

### 资源管理标签

新增后台标签分页接口：

```text
GET /api/admin/tags?page=1&size=20
```

该接口返回 `PageResult<Tag>`，按创建时间倒序、ID 倒序排列，便于新增标签后在第一页看到最新记录。

公开标签接口 `GET /api/tags` 保持全量返回和名称升序，继续服务公开首页标签导航、标签文章页标签名解析、文章编辑页标签选择，不引入兼容风险。

创建标签后回到第一页并重新加载，便于看到最新创建的标签。删除后刷新当前页；如果当前页为空且不是第一页，回退到上一页。

### 仪表盘全站统计

新增后台仪表盘概览接口：

```text
GET /api/admin/dashboard/overview
```

响应包含全站聚合统计和少量待办预览：

- 文章状态计数：草稿、待审核、已发布、已驳回、总数
- 待审核文章预览：最近待审核文章前 5 条
- 用户状态计数：待审核、已启用、已禁用、总数
- 待审核用户预览：最近待审核用户前 5 条
- 标签总数

统计项使用后端 `COUNT` 或 `GROUP BY` 查询全站数据。待办预览可以限制 5 条，这不是统计分页，只是仪表盘入口。

前端仪表盘不再用大 `size` 列表计算全站统计，改为消费概览接口。若概览接口失败，显示错误或空态，不退回到大列表拉取。

## 数据与接口边界

- 本期不新增数据库结构。
- 后台新增接口全部受管理员权限保护。
- 公开接口保持兼容：`GET /api/tags` 不变，`GET /api/articles` 的分页参数不变。
- 后端分页最大页大小应沿用现有服务校验思路，避免前端传入超大 `size`。
- 仪表盘统计不能依赖前端当前页、固定 `size` 或缓存列表。

## 前端交互

- 分页控件仍采用 Element Plus `el-pagination`，保持现有页面风格。
- 当 `total <= size` 时可以隐藏分页控件，沿用现有主列表体验。
- 筛选条件或新增资源导致数据集合变化时，默认回到第一页。
- 删除当前页最后一条数据后，自动回退到可用页。
- 移动端分页控件使用紧凑布局，避免和列表操作按钮重叠。

## 异常处理

- 列表加载失败时保留当前页面结构，显示已有错误提示或空态重试入口。
- 分页请求返回旧响应时，前端应忽略过期结果，避免快速翻页后数据错位。
- 新增后台接口异常不影响公开阅读侧。
- 仪表盘概览失败时不展示错误统计数字。

## 测试与验证

后端建议覆盖：

- 后台标签分页接口返回 `PageResult<Tag>`，按管理员权限保护。
- 仪表盘概览接口使用全站聚合统计，不依赖分页列表。
- 用户、图片已有分页接口保留响应结构。

前端建议覆盖：

- 标签文章页不再出现 `size: 100`，展示分页并使用 `total`。
- 后台用户管理不再固定 `size: 100`，分页切换和操作后刷新正确。
- 资源管理标签和图片不再全量或固定 100 拉取，数量展示来自 `total`。
- 仪表盘不再调用 `getAdminArticles({ page: 1, size: 200 })` 或 `getUsers({ page: 1, size: 100 })` 计算统计。
- 已有分页页面的源码契约不回退。

## 验收标准

- 标签文章页、后台用户管理、资源管理标签、资源管理图片均支持分页加载。
- 页面上展示的总数来自后端分页响应或聚合接口，不使用当前页长度冒充总数。
- 仪表盘展示全站统计，数据量超过前端单页大小时统计仍准确。
- 原有已分页页面不回退。
- 不产生数据库增量脚本。
