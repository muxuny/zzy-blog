# 后台仪表盘交互增强设计

## 背景

后台仪表盘已经升级为“内容运营 + 阅读反馈 + 资源健康”的科技控制台，数据由 `GET /api/admin/dashboard/overview` 聚合接口提供，不再依赖前端大列表统计。当前页面已经具备内容结构、阅读活跃、内容热度、收藏反馈、资源健康和工作队列等模块。交互原型见 `docs/prototypes/后台仪表盘交互增强原型.html`。

现状中已有一部分交互能力：阅读柱图具备悬停明细，待审核文章队列可以直达文章编辑页，待审核用户队列可以跳到用户管理页。但顶部指标卡、热度排行、收藏反馈、状态图例和用户审核落点仍偏静态，管理员看到异常信号后还需要手动定位。

本轮在现有控制台上补齐“可探索、可行动”的交互，不重做仪表盘视觉，不改 dashboard overview 结构。为支持待审核用户精准落点，允许给后台用户列表补充最小 `status` 筛选能力。

## 目标

- 让管理员能从仪表盘核心信号直接进入对应管理页面或详情页。
- 补齐可读悬停明细，使阅读活跃、收藏反馈和结构图例都能在不增加页面复杂度的前提下解释数据。
- 让所有可点击、可跳转、可交互元素在鼠标悬停和键盘聚焦时都有自然反馈。
- 保持当前三套外观主题和浅色/深色/跟随系统兼容，交互反馈全部使用现有主题 token。
- 为后台用户管理补充 `status` 查询参数，支持 `/admin/users?status=pending` 精准展示待审核用户。

## 非目标

- 不新增数据库表、字段或迁移脚本。
- 不扩展 `GET /api/admin/dashboard/overview` 的响应结构。
- 不建设完整 BI 下钻、导出、自定义时间范围或复杂交叉筛选。
- 不做公开侧热门榜、阅读趋势页、点赞、评论或读后反馈。
- 不把收藏反馈命名为新的“收藏趋势”功能；它仍属于仪表盘收藏反馈模块。

## 方案选择

推荐采用“前端交互增强 + 后端用户状态筛选”的小闭环。

- 相比纯前端增强，它能让待审核用户队列精准跳到筛选后的用户列表，而不是只进入用户页。
- 相比完整下钻体系，它不新增复杂接口，不改变 dashboard overview，不把本轮扩大成报表平台。
- 该方案只触及后台仪表盘、后台用户列表和用户列表接口，范围清晰，测试面可控。

## 前端设计

### 仪表盘快捷入口

顶部信号卡从静态 `section` 升级为可访问的操作元素或等价交互结构：

- 全站文章：跳转 `/admin/articles`。
- 待处理队列：优先跳 `/admin/articles?status=pending`；若待审核文章为 0 且待审核用户大于 0，则跳 `/admin/users?status=pending`。
- 全站浏览：跳转 `/admin/articles?status=published&visibility=public`。
- 30 日阅读活跃：保留为数据观察卡，不跳到不存在的阅读历史后台页。
- 资源体量：跳转 `/admin/resources`。

内容热度 Top 5 排行项可点击，直达 `/admin/articles/edit/:id`。没有 `id` 的排行项只展示，不伪装为可点击。

工作队列保持轻量入口：

- 待审核文章：直达 `/admin/articles/edit/:id`。
- 待审核用户：跳转 `/admin/users?status=pending`。

### 数据探索

阅读活跃柱图保留现有悬停气泡，补充键盘聚焦时同样可见的明细反馈。

收藏反馈中的近 7 天新增小柱改为与阅读柱图一致的悬停明细，展示日期和新增收藏次数。无趋势数据时继续显示空态，不展示假数据。

状态与可见性图例支持悬停或聚焦高亮，对应环图和图例行给出轻量强调。图例用于解释当前数据，不作为筛选入口，避免让管理员误以为会修改页面数据范围。

阅读活跃范围提供 `7 / 14 / 30 天` 前端切换，只基于 overview 已返回的 30 天 `dailyReads` 进行切片展示。收藏反馈只展示后端已有的 7 天数据，不伪造 14/30 天收藏反馈数据。

### 用户列表筛选

后台用户页读取 `route.query.status` 初始化筛选，支持 `pending`、`active`、`disabled` 和空值。页面筛选变化时更新列表请求参数，并保留分页行为。

如果 URL 中出现非法 status，前端回退到空筛选并加载全部用户；后端仍负责拒绝非法参数，避免绕过前端时产生含糊查询。

## 后端设计

`GET /api/admin/users` 增加可选查询参数：

```http
GET /api/admin/users?page=1&size=10&status=pending
```

允许值：

- `pending`
- `active`
- `disabled`

空值表示不按状态筛选，保持现有全部用户分页。非法状态抛出业务异常，复用当前统一异常响应。

实现可以继续放在 `AdminUserController`，使用现有 `UserService.page` 和 `LambdaQueryWrapper<User>`。本轮不新增单独 DTO，除非实施时发现现有参数继续扩展会降低可读性。

## 交互与主题约束

所有可跳转、可点击、可聚焦的仪表盘元素必须具备明确反馈：

- 鼠标悬停：轻微浮起、边框高亮、背景层次变化、局部光晕或角标强调。
- 键盘聚焦：使用 `:focus-visible` 提供不低于 hover 的可见反馈。
- 禁用或无跳转目标：不使用 pointer 光标，不展示可点击反馈。
- 动效克制自然，默认不做大幅位移或持续动画。
- `prefers-reduced-motion: reduce` 时取消位移动画，但保留边框、背景、文字或阴影变化等可感知反馈。
- 颜色和阴影使用现有主题变量，例如 `--primary-color`、`--accent-color`、`--panel-bg`、`--border-color`、`--soft-border-color`、`--theme-glow-color`、`--dash-*`，不写死只适合某一外观的颜色。

交互反馈需要兼容松针绿、雾蓝灰、暖铜绿，以及浅色、深色和跟随系统模式。

## 数据流与路由

仪表盘数据仍只来自 `getAdminDashboardOverview()`。前端通过 `buildDashboardStats` 归一化后派生交互状态，例如待处理队列跳转目标、阅读范围切片、可点击排行项。

快捷跳转通过 Vue Router 完成，后台文章页和用户页根据 query 初始化筛选状态。文章页现有筛选能力可复用；用户页新增 status 筛选后支持从仪表盘精准落点。

## 异常与空态

- overview 请求失败时保留当前错误提示和默认空数据。
- 没有热度排行时显示空态，不展示可点击列表。
- 没有收藏反馈趋势时显示空态，不展示悬停气泡。
- 用户列表 status 参数非法时后端返回业务错误；前端从页面控件发起的请求不会产生非法值。
- 跳转目标不存在时不跳转，例如无 id 的排行项只渲染为普通展示项。

## 测试与验证

后端测试：

- `AdminUserController` 默认分页仍返回全部用户。
- `status=pending` 时查询条件包含待审核状态。
- 非法 status 抛出业务异常。

前端测试：

- 仪表盘源码契约包含可点击指标卡、排行直达、队列精准跳转和 hover/focus 反馈样式。
- 收藏反馈小柱具备自定义悬停明细，不只依赖浏览器 `title`。
- 阅读范围切换只使用现有 `dailyReads` 数据，不请求新接口。
- 用户页读取 `route.query.status` 初始化筛选，并向 `getUsers` 传入 `status`。
- 交互样式使用主题 token，不引入固定亮色或暗色硬编码。

最终验证命令：

```powershell
cd D:\03PerProject\blog-backend
mvn -q test

cd D:\03PerProject\blog-frontend
npm.cmd test
npm.cmd run build
```

## 验收标准

- 管理员从仪表盘可以自然进入文章管理、已发布公开文章列表、资源管理、待审核文章编辑和待审核用户列表。
- 所有可跳转或可交互元素在 hover 和 focus-visible 时都有自然、主题化反馈。
- 外观主题切换后，交互反馈仍与当前主题一致，不出现固定蓝色、固定白色或固定深色残留。
- 收藏反馈模块具备近 7 天新增收藏的悬停明细。
- 阅读活跃支持 7/14/30 天前端切换，不新增 overview 字段。
- 后台用户列表支持按状态筛选，`/admin/users?status=pending` 能展示待审核用户。
- 本轮不新增数据库结构，不改变 dashboard overview 响应。
